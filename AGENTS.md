# Agent Guidelines

LexFloatServer Dashboard: a single Vite/React 19 SPA (pnpm, Node 24) that is compiled into the LexFloatServer binary and served by it at `/`, same origin as the API. Stack: TanStack Router, TanStack Query, TanStack Table (via `DataTable`), Tailwind CSS v4, `@cryptlex/web-components`, Paraglide.

Who uses it: the customer's IT admin or ops engineer, activating the server license for each product and checking who holds seats.

## Rules

- Package manager is `pnpm`. Do not use npm or yarn.
- Do not run builds after every change; verify visually or wait for explicit feedback before running `pnpm build`.
- Never cast types: no `as` of any kind (including `as const` and `as unknown as`) and no non-null `!`. Use type annotations or `satisfies`, and fix the type at its source — see [.agents/typescript.md](./.agents/typescript.md).
- Do not hand-edit `src/routeTree.gen.ts` (generated by TanStack Router), `src/lib/api-schema.d.ts` (generated by `pnpm generate:api`) or anything in `src/paraglide/` (generated by the Paraglide Vite plugin).
- Prefer `@cryptlex/web-components` over new components in `src/components/`.
- No hardcoded user-facing text: use Paraglide messages (`m['key']()` from `@/paraglide/messages.js`), defined in [messages/en.json](./messages/en.json).
- The build must stay a static bundle with no server-side rendering, no runtime env vars and no external requests: it ships inside the LFS binary, often on air-gapped networks.
- The dashboard only reads state, except license activation and deactivation.

## UI Conventions

Text wording and capitalization rules are in [messages/AGENTS.md](./messages/AGENTS.md).

- **Capitalization**: every title and button is Title Case: page, section, card, banner and dialog titles, labels, column headers, nav and menu items, status values and button text ("Activate License", "Lease Duration", "Log Out"). Sentence case only for running text: hints, descriptions, toasts, errors and input placeholders.

- **Filters**: list filter properties in alphabetical order. Sort dropdown options alphabetically unless the values have a natural order (e.g. severity, time ranges).
- **Row/menu actions**, in this order: actions that change the resource (Activate, Deactivate), then actions that don't (e.g. Copy, View), then links to other pages.
- **Dates and times**: the LFS API returns epoch **seconds**, not ISO strings. Format with `formatDate` from `@cryptlex/web-components/utilities/date` and the helpers in `src/lib/relative-time.ts` / `src/components/expiry-value.tsx`, which follow the viewer's locale via `Intl`; never hardcode a date format.
- **Numbers**: use locale thousands separators and consistent decimal places for similar values.
- **Single product**: most servers host one product. Hide product columns, filters and pickers when there is only one (see `hasManyProducts` in `src/routes/_app/devices/index.tsx`).
- **Forms**: show validation errors on blur, mark required fields, and show the error next to the field it belongs to.
- **Layout**: uniform spacing between similar elements, aligned fields and labels, and layouts that hold up at mobile widths.

## Architecture

- `src/main.tsx` — creates the `QueryClient` and router; router context carries `queryClient` and `branding`.
- `src/lib/api.ts` — the typed `openapi-fetch` `client`, bearer-token middleware, `ApiError` (every non-2xx throws), and token helpers (`isLoggedIn`, `getAccessToken`, …). A 401 clears the token and reloads at `/login`.
- `src/lib/queries.ts` — shared `queryOptions` for every GET (`productsQuery`, `productQuery`, `serverStatsQuery`, …). Add new reads here, not inline in components.
- `src/global.d.ts` — registers the generated `paths` / `operations` / `components` with `@cryptlex/web-components/utilities/api-types`, so `ApiSchema`, `ApiResponseBody`, `ApiQuery`, `getColumnHelper` and `useCtxClient` are typed against the LFS API.
- `src/components/` — app-level components shared by more than one page. Page-specific components stay next to the route as `-name.tsx`.

### Routes

File-based under `src/routes/`:

| Pattern | Meaning |
|---|---|
| `_app/` | Pathless layout: auth guard, sidebar, breadcrumbs; loads `productsQuery` once for every page |
| `-prefixed.tsx` | Excluded from routing; co-located component (e.g. `-activate-dialog.tsx`) |
| `index.tsx` | List view |
| `$id.tsx` | Details view, `$id` is the route param |

LFS returns `index.html` for unknown paths, so routes use normal URLs. A URL must not end in a dotted segment like `/clients/10.0.4.18` — put such values in search params instead.

Each route sets breadcrumbs in `beforeLoad` with `routerBreadcrumbs([...])` and its tab title in `head` with `m['common.pageTitle']({ title, appName })`.

## Code Style

Biome config: 4-space indent, 120 line width, single quotes, semicolons, trailing commas `es5`, `arrowParentheses: asNeeded`.

- `console.*` calls are a lint **error**.
- TypeScript strict mode: `noUnusedLocals`, `noUnusedParameters`, `verbatimModuleSyntax` — use `import type` for type-only imports.
- Import app code with the `@/` alias (`@/lib/api`), not relative `../` paths.
