# TypeScript Conventions

## Never cast types

No `as` of any kind — not `as Type`, not `as unknown as Type`, not `as const` — no non-null `!`, and no manual generic type arguments (`<Type>`) where inference works. If a cast feels necessary, the fix belongs upstream:

1. **Schema validation** is the source of truth (the LFS OpenAPI spec via `ApiSchema`, zod).
2. **Type inference** from function return types, loaders, and API responses — let TypeScript derive the type instead of asserting it.
3. **Fix at source** (schema, query function, function signature) rather than casting at the point of use.

To check a value against a type, annotate it or use `satisfies`; neither overrides the type:

```ts
// Bad
const INCLUDE = ['license.meterAttributes', 'metadata'] as const;
const filters = { ... } as unknown as DeviceFilters;

// Good
const INCLUDE: ApiQuery<'listProducts'>['include'] = ['license.meterAttributes', 'metadata'];
const filters = { ... } satisfies DeviceFilters;
```

If `satisfies` fails, the object doesn't match the type — fix the object or the type, don't cast around it.

## API types — generated from `swagger.json`

`src/lib/api-schema.d.ts` is generated by `pnpm generate:api` from `swagger.json` (the LFS OpenAPI spec, not committed — get the current one from the LexFloatServer repo). Never edit it by hand and never hand-write request or response shapes.

`src/global.d.ts` registers the schema with `@cryptlex/web-components`, so its type helpers resolve against the LFS API:

```ts
import type { ApiQuery, ApiResponseBody, ApiSchema } from '@cryptlex/web-components/utilities/resources';

// Item type of a list operation
type Device = ApiResponseBody<'listFloatingLicenses'>;

// Query params of an operation
type ProductsQuery = ApiQuery<'listProducts'>;

// A named schema
function ProductCard({ product }: { product: ApiSchema<'Product'> }) { ... }
```

Check the generated file for the exact operation IDs and schema names.

## Queries

Reads go through `queryOptions` in `src/lib/queries.ts`, built on the typed `client` from `src/lib/api.ts`. Path strings, params and response types are all checked against the spec. The `queryKey` is `['get', '<path>', ...params]`.

```ts
export const productConfigQuery = (productId: string) =>
    queryOptions({
        queryKey: ['get', '/api/v4/products/{productId}/server/config', productId],
        queryFn: async () =>
            (await client.GET('/api/v4/products/{productId}/server/config', { params: { path: { productId } } }))?.data,
    });
```

Non-2xx responses throw `ApiError` (`status`, `code`, `message`), so `data` is always set when a call resolves. Branch on `error.code` / `error.status`, not on the message text.

Route loaders prefetch through `context.queryClient`; components read with `useSuspenseQuery(productsQuery)` / `useQuery(...)`. `productsQuery` is loaded once by the `/_app` layout, so pages read it from the cache instead of refetching.

## Mutations

Use the typed client so the body type is inferred from the spec, and invalidate the affected queries:

```ts
const mutation = useMutation({
    mutationFn: async () =>
        await client.POST('/api/v4/products/{productId}/server/activate', { params: { path: { productId } }, body }),
    onSuccess: () => {
        toast({ variant: 'success', title: m['productsPage.activateDialog.toast.success']({ product: product.displayName }) });
        queryClient.invalidateQueries({ queryKey: ['get'] });
    },
});
```

See `src/routes/_app/products/-activate-dialog.tsx` and `-deactivate-dialog.tsx` for the working examples.

## TanStack Router type safety

- `createFileRoute('/_app/products/$productId')` — the route id literal is checked against the generated route tree.
- `Route.useParams()` / `Route.useLoaderData()` / `Route.useRouteContext()` / `Route.useSearch()` — always use these typed hooks.
- Validate search params with zod: `validateSearch: z.object({ ... })`. `Route.useSearch()` is then fully typed.
- Navigation is literal-checked: `<Link to="/products/$productId" params={{ productId }} />`, `navigate({ to: '/devices' })`, `throw redirect({ to: '/login' })`.
- Never edit `src/routeTree.gen.ts` — it regenerates from the files in `src/routes/`.

## Generic Type Parameter Naming

All generic type parameters must be prefixed with `T`.

```ts
// Bad
function withRetry<Args extends unknown[], R>(fn: (...args: Args) => R) { ... }

// Good
function withRetry<TArgs extends unknown[], TReturn>(fn: (...args: TArgs) => TReturn) { ... }
```

Common names: `T`, `TArgs`, `TReturn`, `TData`, `TError`, `TKey`, `TValue`.
